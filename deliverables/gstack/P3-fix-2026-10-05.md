## 1. P3-1：安全响应头

### 落点
`app/main.py`（`_SECURITY_HEADERS` + `_security_headers_middleware`）。

```
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Referrer-Policy: no-referrer
Content-Security-Policy: default-src 'self'; script-src 'self' 'unsafe-inline';
  style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; connect-src 'self';
  object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'
```

### 设计要点
- **定义顺序**：放在 `_local_access_guard` **之后**。Starlette 后添加的中间件在最外层，因此安全头会加在**所有**响应上，包括守卫直接返回的 403（已用真实服务验证）。
- **CSP 为何仍留 `'unsafe-inline'`**：本工具零构建、JS/CSS 全部内联，这是当前架构下的必要让步。CSP 在此的价值是**禁止加载外部脚本、禁止 object/embed、禁止被第三方页面嵌框、限制表单外发与 base 篡改**，并为将来把内联脚本外移后进一步收紧（去掉 `'unsafe-inline'`）预留位置。
- **不破坏应用**：全站无外部资源依赖（脚本/样式/图片全部同源；唯一外链是 GitHub 导航 `<a>`，CSP 不拦导航），无 `eval`/`new Function`/Worker/WebSocket/`createObjectURL`/`data:image`。

## 2. P3-2：缩小 getaddrinfo monkeypatch 范围

### 根因
直连 IP 覆盖原先替换**进程级** `socket.getaddrinfo`——影响范围内的一切 socket（含 ASGI 服务器自身）。

### 改法
`app/direct_connect.py` 改为只 patch `urllib3.util.connection.create_connection`（`_patched_create_connection` / `enable_direct`），`_validate_ip` 临时 patch 同一收窄目标并委托到真正的原始函数（避免被 `.env` 旧 IP 覆盖）。

### 为何功能完整（安全官复核确认）
- urllib3 2.8.0 的 `HTTPConnection._new_conn` 以**模块属性** `connection.create_connection(...)` 调用，模块属性补丁生效。
- 所有 Pixiv 路径（`pixiv.py` 各 Session、`download.py`、`fetch_profile_image`）都走 requests/urllib3；DoH 用裸 socket 连固定 IP，无需解析；全库无其它 `getaddrinfo` 引用。
- 运行时探针确认：`enable_direct()` 后 `socket.getaddrinfo` **未变**，仅 urllib3 连接创建函数被替换。

## 3. P3-3：扫描 / 同步分批提交

### 根因
`scan_directory` / `sync_metadata` 把整个循环包在**单个事务**里，长任务期间独占 SQLite 写锁，UI 的并发写只能干等。

### 改法
改用 `get_connection()` + `try/except(rollback)/finally(close)`：
- **扫描**：每 `COMMIT_BATCH_SIZE`（200）个作品 `commit()` 一次；取消路径先 `commit()` 保留已完成部分；`_prune_duplicates`/`_prune_missing` 后最终提交。
- **同步**：在循环**开头**每 `SYNC_COMMIT_BATCH_SIZE`（25）行 `commit()` 上一批——`continue`/`break` 都能自然落盘；循环后最终提交。

### QA 实证（无数据丢失）
注入中途异常后：**已提交批次保留、当前未提交批次回滚**（重扫幂等，无永久丢失）；计数器与 summary 正确；prune 仍在循环后执行并提交；同步的 `continue`（网络失败 / 已删除）与 `break`（认证失败）路径写入均落盘。

> **设计取舍（非缺陷）**：中途提交意味着并发读可能看到"部分扫描"状态，这是为换取不长时间独占写锁的自觉取舍。

## 4. P3-4：单实例锁接管原子化（经复验重做）

### 初版与其缺陷
初版把「`os.remove` 陈旧锁 + 重试 O_EXCL 创建」改为「`os.rename` 到独占名 + 创建」。

**QA 的负向对照发现该测试对原子性零鉴别力**，深挖后确认根因：rename 本身并不能完全消除竞态——若**迟到的 rename 落在别人已重建新锁之后**，它会把**别人的新锁**搬走，仍可能双赢。

### 重做后的方案
```python
raw = _lock_content(lock_path)            # 判陈旧时读到的原始内容
if not _raw_is_stale(raw, lock_path): return None
stale_path = "%s.stale.%d.%s" % (lock_path, os.getpid(), uuid.uuid4().hex)  # 全局唯一
try: os.rename(lock_path, stale_path)     # 原子搬移，只有一个进程能移走
except OSError: return None
if _lock_content(stale_path) != raw:      # 复核：移走的不是刚才那把陈旧锁
    try: os.rename(stale_path, lock_path) #    → 放回原位并放弃
    except OSError: pass
    return None
os.remove(stale_path); continue
```
- **内容复核**：确认搬走的确实是判定为陈旧的那把；若内容已变（被别人换成活锁）则放回并放弃，**不抢别人的锁**。
- **唯一临时名**：初版用 `.stale.<pid>`，同进程多线程会撞名互搬（调试实测会出现"双方都放弃、0 赢家"）；改为 `uuid` 后消除。

### 新增的两条测试（有鉴别力）
- **确定性测试**：模拟「判陈旧之后、接管之前，锁被别人换成活锁」→ 断言放弃并放回。**负向对照实测：改回 `os.remove` 写法后该断言变红**（旧写法会抢走别人的活锁）。
- **并发测试**：2 线程用屏障同步「判陈旧」后并发抢同一把陈旧锁，15 轮**每轮恰好 1 个赢家**（连跑 3 次稳定）。

## 5. P3-5：依赖锁 + 移除 `--trusted-host`

- **移除 `--trusted-host`**：`install.bat` 不再关闭 pip 对 PyPI 的 TLS 校验（原写法让中间人可替换下载内容）。README 同步更新，并说明如需绕过自签证书应使用 `PIP_CERT`。
- **`requirements.lock`（含哈希）**：锁定 `requirements.txt` 解析出的**完整依赖闭包**（30 个包），每个包列出 Windows + CPython 3.10–3.13 各轮子的 `sha256`（共 42 条哈希）。`pip install -r requirements.lock --require-hashes` 已实测通过。
- **`install.bat`**：优先用锁做带哈希校验的安装；若本机解释器不在覆盖范围内则**回退 `requirements.txt`**（避免因平台/Python 版本不匹配而安装失败）。
- **生成工具**：`tools/gen_requirements_lock.py`（对 3.10–3.13 各解析一次并合并哈希），已实测可复现同一份锁。

## 6. 额外修复：测试套件不再"静默通过"

**安全官发现**：当有实例持锁导致真实服务起不来时，`run_all.py` 用 `skipped_module` 记跳过——**live 用例一项没跑，摘要却仍报"全部通过"、退出码 0**（安全官首轮运行即因此漏跑了整个冒烟模块）。

**改法**：新增 `failed_module()`，服务启动失败分支改记**失败**。实测：后台持活锁运行套件 → `失败 2 / 退出码 1`（此前为静默跳过 + 退出码 0）。

## 8. 残余风险（不阻塞）

| 级别 | 项 | 说明 |
|---|---|---|
| Medium（设计性，实际 Low） | CSP 的 `script-src 'unsafe-inline'` | 内联脚本架构下无法避免；当前无已知注入点（内联 JS 只嵌入数字 ID，模板 Jinja2 转义到位）。待内联脚本外移后可去掉。 |
| Low / Info | 500 响应无安全头 | `ServerErrorMiddleware` 在用户中间件之外，未处理异常的 500 不经过安全头中间件。 |
| Info | `img-src data: blob:` 可再收窄 | 全站无 `createObjectURL`/`data:image`，可收窄为 `'self'`。 |
| Info | `_validate_ip` 临时 patch 模块属性 | `refresh_ips` 受单任务锁串行，`forced()` 仅重写目标主机。 |
| Low（既有） | `_prune_missing` 的文件系统副作用 | 若其后提交失败，DB 与磁盘可能不一致（单事务版同样存在，属 P1-9）。 |
| Low（既有） | 测试结束时可能残留陈旧 `.instance.lock` | `harness.Server.stop()` 用 `terminate()`，Windows 下 `run.py` 的 `finally` 未必执行；因陈旧锁可被接管，不影响后续运行。 |
