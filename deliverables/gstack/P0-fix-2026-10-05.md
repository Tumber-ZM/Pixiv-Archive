## 1. P0-1：前端存储型 XSS 修复

### 1.1 根因

`app/templates/index.html` 中有 9 处内联事件处理器（`onclick="fn('...')"`）用 `escapeAttr()` 把**用户可控字符串**拼进 JS 字符串字面量。

关键缺陷：HTML 规范要求浏览器在**编译内联事件处理器之前**先对属性值做一次 HTML 实体解码，因此 `escapeAttr()` 产出的 `&#39;` 会被还原为 `'`，击穿 JS 字符串闭合 —— 攻击者只需在收藏夹名 / 标签名 / 作者名里写入 `');alert(document.domain);//` 即可执行任意脚本（存储型 XSS）。

### 1.2 修复方案

将 9 处内联 `onclick` 全部改为 `data-act` + `data-*` 属性承载数据，用**一处捕获阶段事件委托**统一分发。数据不再进入 JS 源码上下文，实体解码不再构成威胁。

**9 个动作映射**（`app/templates/index.html:1991`）：

| `data-act` | 数据属性 | 调用 |
|---|---|---|
| `tile-fav` | `data-id` | `openFavSelect(id)` |
| `tile-delete` | `data-id`、`data-title` | `deleteArtworkFromTile(id, title)` |
| `filter-author` | `data-name` | `filterByAuthor(name)` |
| `filter-fav` | `data-id`、`data-name` | `filterByFavorite(id, name)` |
| `fav-delete` | `data-id`、`data-name` | `deleteFavorite(id, name)` |
| `sub-delete` | `data-uid`、`data-name` | `deleteBookmarkSub(uid, name)` |
| `viewer-author` | `data-id`、`data-name` | `closeViewerToAuthor(name, id)` |
| `viewer-tag` | `data-name` | `closeViewerToTag(name)` |
| `viewer-fav` | `data-id`、`data-name` | `closeViewerToFavorite(id, name)` |

**委托代码块**（`app/templates/index.html:1984` 起）：

```javascript
// ===== 事件委托（data-act）=====
const _ACTIONS = {
    'tile-fav': el => openFavSelect(Number(el.dataset.id)),
    'tile-delete': el => deleteArtworkFromTile(Number(el.dataset.id), el.dataset.title || ''),
    'filter-author': el => filterByAuthor(el.dataset.name || ''),
    'filter-fav': el => filterByFavorite(Number(el.dataset.id), el.dataset.name || ''),
    'fav-delete': el => deleteFavorite(Number(el.dataset.id), el.dataset.name || ''),
    'sub-delete': el => deleteBookmarkSub(Number(el.dataset.uid), el.dataset.name || ''),
    'viewer-author': el => closeViewerToAuthor(el.dataset.name || '', Number(el.dataset.id)),
    'viewer-tag': el => closeViewerToTag(el.dataset.name || ''),
    'viewer-fav': el => closeViewerToFavorite(Number(el.dataset.id), el.dataset.name || ''),
};

document.addEventListener('click', function (e) {
    const el = (e.target && e.target.closest) ? e.target.closest('[data-act]') : null;
    if (!el) return;
    const handler = _ACTIONS[el.dataset.act];
    if (!handler) return;
    e.preventDefault();
    e.stopPropagation();
    hideCtxMenu();
    const sm = $('sortMenu');
    if (sm) sm.classList.add('hidden');
    handler(el);
}, true);
```

### 1.3 三个关键设计点

1. **捕获阶段（第三参 `true`）**：瓦片本身也绑定了「打开查看器」的点击处理，若委托用冒泡阶段，点删除/收藏按钮会**先**触发查看器。改用捕获阶段并在命中后 `stopPropagation()`，确保动作优先且互不干扰。
2. **补做被截断的副作用**：原内联 `onclick` 里除了调用主函数，还夹带了 `hideCtxMenu()` 与关闭排序菜单。改为委托后这些副作用必须显式补回（否则右键菜单/排序菜单不会自动收起）。
3. **`data-*` 原样承载**：数据以属性值形式存在，浏览器只在取值时做一次解码，取回的就是原始字符串（含单引号也原样传递），不再有二次解码击穿问题。

## 2. P0-2：本机访问守卫（Host / Origin / Referer）

### 2.1 根因

服务固定绑 `127.0.0.1`，但**任何网页**都能向本机发起请求，存在两类攻击：

- **DNS rebinding**：恶意域名先解析到攻击者服务器，再把解析改到 `127.0.0.1`，浏览器视其为同源，攻击者页面即可读写本机 API。浏览器**无法伪造 Host 头**，故校验 Host 可挡。
- **本机 CSRF**：无请求体的 POST 属 CORS「简单请求」，跨站 `<form>` / `fetch` 不触发预检，可直接打本机写接口。校验 Origin / Referer 可挡。

### 2.2 修复方案

在 `app/main.py:70` 起新增访问守卫中间件：

```python
_LOCAL_HOSTNAMES = frozenset({"127.0.0.1", "localhost", "::1", "[::1]"})
_UNSAFE_METHODS = frozenset({"POST", "PUT", "PATCH", "DELETE"})

def _hostname_of(value):            # 剥离端口 / 处理 IPv6 括号
    ...
def _origin_hostname(value):        # urlsplit 取 hostname
    ...

@app.middleware("http")
async def _local_access_guard(request: Request, call_next):
    host = _hostname_of(request.headers.get("host", ""))
    if host and host not in _LOCAL_HOSTNAMES:
        return JSONResponse({"detail": "仅允许通过本机地址访问"}, status_code=403)
    if request.method in _UNSAFE_METHODS:
        origin = request.headers.get("origin")
        if origin is not None:
            if _origin_hostname(origin) not in _LOCAL_HOSTNAMES:
                return JSONResponse({"detail": "已拒绝跨站请求"}, status_code=403)
        else:
            referer = request.headers.get("referer")
            if referer and _origin_hostname(referer) not in _LOCAL_HOSTNAMES:
                return JSONResponse({"detail": "已拒绝跨站请求"}, status_code=403)
    return await call_next(request)
```

### 2.3 策略要点

- **Host 校验对所有方法生效**（GET 也挡 DNS rebinding 读取）。
- **Origin/Referer 校验只对写方法生效**：无请求体的简单 POST 才需要防；带自定义头的请求会触发预检，浏览器已代为把关。
- **Origin 优先，Referer 回退**：浏览器跨站写请求必带 Origin；无 Origin 时才看 Referer。两者都无（非浏览器客户端，如 curl）则放行，不影响本机脚本/自动化。
- **空 Host 放行**：避免极端环境下无 Host 头导致服务不可用。

## 3. P0-3：事件循环阻塞修复

### 3.1 根因

`api_add_bookmark_sub`（`app/main.py:987` 附近）是 `async def`，但在事件循环里**直接**调用了同步阻塞的 `get_pixiv_client().get_user_display_name(uid)`（底层是 `requests` 网络调用，最长阻塞 `REQUEST_TIMEOUT` 秒）。阻塞期间整个 ASGI 事件循环停摆，**所有**请求无响应。

### 3.2 修复方案

```python
name = (body.get("name") or "").strip()
if not name:
    # 取用户名是同步阻塞的 HTTP 调用（最长 REQUEST_TIMEOUT 秒）。本端点是 async def，
    # 直接在事件循环里调用会卡住整个服务（期间所有请求无响应），故丢到线程池执行。
    name = await run_in_threadpool(get_pixiv_client().get_user_display_name, uid)
```

`run_in_threadpool` 来自 `starlette.concurrency`（`app/main.py:13`），把阻塞调用移出事件循环到线程池，`await` 期间事件循环可继续处理其他请求。

## 5. 残余风险（全 P3，不阻塞）

安全官在复验中登记 6 条边界情形，均判定**不可由浏览器构造**或**属有意设计**，不阻塞放行：

1. **Host 解析怪癖** `127.0.0.1:80@evil.com` 被判本机 —— 浏览器视 `127.0.0.1:80` 为 userinfo，无法构造此 Host。
2. **尾点 FQDN** `localhost.` / `127.0.0.1.` 被 403 —— 罕见潜在误伤，与守卫自洽。
3. **Origin/Referer 解析怪癖** `http://127.0.0.1:6814.evil.com` —— 浏览器不会构造此类 Origin。
4. **白名单死条目裸 `::1`** —— `_hostname_of` 对无括号 `::1` 返回 `":"`，实际靠 `[::1]` 分支；`_origin_hostname` 会用得到，属有意双写。
5. **Origin/Referer 校验忽略端口** —— 能托管 localhost 页面的攻击者已具本地代码执行能力。
6. **无 Origin 且无 Referer 的写请求放行** —— 面向非浏览器客户端；浏览器跨站写必带 Origin。

**范围外（P1/P2，已登记待后续）**：F-009（`create_date` 未转义，Low）、F-008（`tag.html:27` 内联 Jinja 变量，当前不可利用，Low）、直连 TLS（Medium 设计取舍）、token 前 8 字符回显（Low，F-003 修复后已难读取）。

**QA 记录的观察（P3）**：陈旧 `.instance.lock` 遗留（PID 已死）属测试非优雅退出的正常产物，`acquire_single_instance()` 会接管；async 端点（如 `api_batch_delete_artworks`）仍做同步 SQLite/文件操作，大量文件时可能短时卡顿（本地有界操作，非网络级阻塞，本批次不处理）。
